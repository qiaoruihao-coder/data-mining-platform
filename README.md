# AI 家装平台：数据挖掘课程项目

项目以家装需求、服务方匹配和履约管理为场景，结合住宅案例聚类与面向业主和服务方的双向推荐。仓库收录桌面版平台源码快照，以及 2026-11-21 更新的答辩 PPT。

## 功能

- 业主端：需求澄清、案例推荐、服务方匹配、报价核对、排期与履约记录、评价和售后。
- 服务方端：需求大厅、基于本人历史订单的推荐、报价与订单管理；支持同城、自选城市和全国范围。
- 管理端：需求、服务方、评价与售后记录查看。
- 数据挖掘：案例多视图加权 K-means、需求聚类、历史偏好推荐；另保留离线分类和聚类实验。

案例数据位于 `ai-home-platform/experiments/source-audit/domestic-live.json`。接口优先读取该文件；文件缺失时使用内置的 32 个案例和 6 个簇。聚类时，类别视图权重为 0.8，数值视图权重为 0.2；测试 2 至 6 个簇，每种设置初始化 20 次。业主推荐按面积、造价和需求分别赋予 42%、33% 和 25% 的权重。有历史订单的服务方推荐按相似度、群体占比和专长分别赋予 75%、20% 和 5% 的权重；没有历史订单时使用冷启动规则。

案例来自近期可采集到的公开网页，不代表整个装修市场。参考造价不是平台报价，设计机构所在地也不代表其服务范围。由于没有真实的用户偏好和成交标签，项目不报告推荐准确率。齐家网和土巴兔目前只做过来源调研，案例集尚未接入这两个平台的数据。

## 本地启动

需要 Node.js 20.19 或更高版本，建议使用 22，并安装 npm。

```powershell
git clone https://github.com/qiaoruihao-coder/data-mining-platform.git
cd data-mining-platform/ai-home-platform
npm.cmd ci
Copy-Item .env.example .env
npm.cmd run db:setup
npm.cmd run dev
```

启动后访问 `http://localhost:3000`。macOS/Linux 用户将 `npm.cmd` 换为 `npm`，并用 `cp .env.example .env` 复制环境文件；已有 `.env` 配置不要覆盖。维护者可运行 `npm run owner:create` 创建业主账号，仓库不提供真实账号凭据。案例页面通过 `/api/cases` 读取附带快照。离线实验所需依赖见 `experiments/mining/requirements.txt`。

## 演示边界

AI 需求澄清默认使用 mock，可通过服务端环境变量接入模型。照片上传不等同于图像分析，真实图像分析尚未实现。付款流程只模拟业务状态，不处理真实资金。公开服务方信息和演示历史包含合成数据，不能视为真实成交。

固定示例中的两份报价小计分别为 12,000 元和 13,000 元。清运费用仍待确认，两份报价的地面单位不同，成品保护项目也不一致，因此不能据此认定最终报价更低。

本地业务数据库、账号、用户照片、密钥、依赖和缓存均未上传。源码不会自动迁移数据库中的临时演示订单。种子数据和脚本可用于复现实验，不代表平台完成过真实交易。
