## 使用方式

开启公开自动登录后，访问业主、服务方或平台运营页面会自动登录对应原账号，无需输入密码。已有需求和历史记录继续使用原数据库。

这是公开体验入口，持有链接者可查看和修改对应账号的数据。请勿提交真实个人敏感信息。账号密码不会写入前端或上传仓库。

| 角色 | 功能 |
|---|---|
| 业主 | 需求澄清与管理、案例推荐、服务方匹配、报价比对、排期、履约记录、评价与售后 |
| 服务方 | 需求大厅、历史偏好推荐、报价管理、接单与履约跟进 |
| 平台运营 | 需求、服务方、评价和售后记录查看 |

## 本地开发

需要 Node.js 20.19及以上版本，建议 Node.js 22。以下命令仅用于全新开发目录和独立开发库。已有配置不要覆盖，已有业务数据库不要运行初始化或种子脚本。

```powershell
git clone https://github.com/qiaoruihao-coder/data-mining-platform.git
cd data-mining-platform/ai-home-platform
npm.cmd ci
Copy-Item .env.example .env
npm.cmd run db:setup
npm.cmd run dev
```

访问 `http://localhost:3000`。macOS/Linux 将 `npm.cmd` 换为 `npm`，复制命令改为 `cp .env.example .env`。

## 原数据库部署

先备份原库，配置 `DATABASE_URL` 指向该数据库，并明确设置服务端账号 ID：

| 配置项 | 用途 |
|---|---|
| `PUBLIC_ACCOUNT_ACCESS` | 设置为 `true` 开启公开自动登录 |
| `PUBLIC_OWNER_ID` | 已存在的原业主账号 ID |
| `PUBLIC_PROVIDER_ID` | 已存在的服务方账号 ID |
| `PUBLIC_ADMIN_ID` | 已存在的平台运营账号 ID |
| `ISOLATED_DEMO` | 原账号实例保持 `false` |

在应用目录构建并启动：

```powershell
npm.cmd run build
node scripts/start-public-access.mjs
```

脚本默认监听 `127.0.0.1:3101`，设置内部服务地址并开启公开自动登录。对外使用 HTTPS，保留会话 Cookie 的 Secure 属性。恢复密码登录时，停止该脚本，关闭 `PUBLIC_ACCOUNT_ACCESS`，改用普通启动命令。

生产服务运行时不要重建同一个构建目录。域名和隧道配置属于部署环境，不包含在业务数据库中。
