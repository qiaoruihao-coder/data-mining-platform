# A 的变更请求：接通真实需求澄清模型

- 提出角色：A
- 状态：待 D 配置和验收

## 目标

需求澄清页面已经按公共 `ChatResult` 契约接线。当前页面可以展示模拟结果并让业主核对后提交，但真实模型调用由 D 的服务端 LLM 网关负责，A 不修改公共 API、依赖、环境配置或 `src/lib/llm.ts`。

## D 需要确认的实现

1. 在服务端配置真实模型供应商的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，并以 `AI_MODE=live` 启用；密钥只能由服务端读取。
2. 真实模型响应继续严格校验为公共 `ChatResult`，缺字段、臆造金额或非法枚举必须返回失败，不降级成模拟成功。
3. 保留现有超时、有限重试和 503/`AI_UNAVAILABLE` 失败语义；模型未配置或不可用时，页面显示“需求助手暂时不可用”，不伪装为实时结果。
4. 用隔离测试或受控供应商响应验证 `meta.source = "live"`、完整草稿、缺失字段和非法 JSON；不得在仓库提交密钥或真实用户内容。

## A 侧验收

- 页面只依赖 `POST /api/demand/chat` 的公共信封，不读取供应商字段。
- `meta.source = "mock"` 时显示“模拟结果”，`live` 时显示“实时结果”。
- 页面不再向业主展示 API 路径、D 角色名、`AI_MODE`、HTTP 状态码或内部错误码。

## 2026-11-15 本地演示复现与接入缺口

- 基线：main `de40a7b`。本地预览使用独立演示库与 `AI_MODE=mock`；仅检查配置是否存在，确认项目 `.env` 的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 均为空。
- 向实际 `/api/demand/chat` 发送“深圳60平方米老房，做适老化改造，卫生间防滑并加扶手，预算3万到5万元，希望30天完工。”，仍返回固定追问、`ready:false`、`draft:null` 和全部六个缺失字段，来源为 mock。
- 原因：`clarifyDemand` 的 mock 分支不分析输入。页面请求链路可用不等于真实 AI 已接通，继续对话也不会产生草稿。
- A 修正模拟模式说明，将模拟缺失字段标为追问示例，不再断言用户没有填写，保留手动填写入口；这不构成真实 AI 接入。

### 服务端具体变更请求

1. `src/lib/llm.ts` 当前提示只引用 `ChatResult` 名称，未向模型提供实际结构。请依据 `src/contracts/index.ts` 明确输出 `reply`、`ready`、`draft`、`missingFields`，以及 `DemandInput` 的字段、数值单位和改造类型枚举；不新建替代 DTO。
2. 缺信息时 `ready:false`、`draft:null`，只追问对话中尚未提供的字段；信息齐全时输出可校验的完整草稿、`ready:true`、空缺失列表。3–5 万元应为 3000000–5000000 分，不能把用户未提供的预算或面积补为默认值。多轮补充和纠正应依据整段对话。
3. 由维护者在服务端配置选定供应商并启用 live。不要复用其他应用凭据，不提交密钥，不把配置或供应商错误细节暴露给浏览器。实际模型调用需使用合成装修描述验收。
4. 受控响应测试覆盖协议，但还需真实供应商验证：完整描述生成草稿；缺预算时仅追问预算；补充预算后完成；纠正城市/金额后更新。错误 JSON、错误枚举、超时和缺配置继续 503，不能回退 mock。若修改接口行为，在同一 PR 更新 `scripts/smoke.mjs`，普通 CI 不依赖真实密钥。

验收必须分别记录受控响应与真实供应商结果。在真实调用完成前，保持“待配置与真实验收”状态。
