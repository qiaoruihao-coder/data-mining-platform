# B：连续档期窗口匹配与展示

基于已合入的 D #148 档期契约、#151 服务端依赖边界修复与 B #149 评价排序，完成 B P1 的档期部分。仅修改 B 目录；不改公共契约、依赖、配置或数据库，不需要新增共享字段。

## 规则与验收

- 城市/施工工种硬过滤、标签与基础评分不变。先按基础分降序；同基础分组满足原评价条件时按评价均分降序。
- 档期单独以整个基础分组为准：所有成员均有契约有效、读取时未过期且同来源的档期，才启用下一层细排。前序规则仍同序时，有一段剩余连续窗口能容纳 `Demand.desiredDays` 的候选优先；最终按 ID 稳定展示。不跨基础分组，不覆盖有效评价顺序，不按更早开工或更长窗口加分。
- 窗口按 Asia/Shanghai 自然日解释，含首尾；早于读取当天的部分截断，不累计分散窗口，也不拼接单独列出的相邻窗口。没有期望起止日期，只能比较连续天数，不能判定某个截止日期前能完工。
- 缺省/null/非法或缺来源的档期是未知；确认空数组及所有窗口已结束，表示覆盖范围内没有剩余窗口；剩余窗口短于需求表示天数不足。未知不按零天处理，也不淘汰候选。
- `now >= validUntil` 或上海当日超过 `coverageEndDate` 即待更新，不参与排序。更新时间晚于读取时钟时保守标未知，提示核对设备时间。公共契约仍可解析过期/未来时间，不修改 D 的解析行为。
- 浏览器读取需求和目录后捕获一个 `readAt`，算法、卡片共享此时点。页面显示 UTC 读取时间、原始窗口、剩余窗口/天数、覆盖范围、档期来源、更新时间和有效截止。明确为读取快照，停留期间不自动更新，点击“刷新匹配”重新读取及计算。API 每次请求在本次计算时判断有效性，继续 no-store。

## 来源与限制

复用 `src/contracts` 的 Provider/ProviderAvailability/Demand 类型。目录固定窗口仍为 **mock**，卡片逐条标“mock · 固定模拟窗口”；不新增模拟生产数据或 mock 评价切换。默认 live 评价无样本不回退 mock。规则计算未调用 AI。

本功能不是预约、产能锁定、日期承诺或真实档期维护。真实档期录入、多班组容量、服务方确认和需求起止日期输入未实现。当前使用各调用方读取时钟，设备时钟错误可能导致档期判断不同；页面如实显示时点并允许刷新，没有跨设备时钟同步或后台自动刷新。

专项测试使用明确合成的 2028 年契约夹具，不写数据库；覆盖上海午夜、闰日/跨月/跨年、单日窗口、窗口不拼接、截止点、覆盖过期、缺来源、未来更新时间、基础分/评价优先、整组降级、全排列稳定、输入不可变、来源展示及刷新到期。
