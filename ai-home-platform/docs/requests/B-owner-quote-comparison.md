# B：业主报价页按需求查询与逐条来源

基线：2026-11-14 的 origin/main `6b0561b`，已包含 #79、#87 和 #90。本次只修改 B 的页面、组件和测试；不改公共契约、配置、依赖或鉴权基础设施。

## 页面行为

- `/owner/quotes/<id>` 首先请求 `GET /api/quote?demandId=<编码后的原始 ID>`，保留 ID 首尾空格，不再调用无参数演示报价接口。通过后才读取需求详情与可选服务方资料。
- 401 提示在页面上方登录业主账号后重新加载；403 提示服务方身份不能读取业主比较列表，角色导航不等于登录。两种失败均停止后续请求，不展示空成功或回退 mock。
- 报价查询和需求详情的 `404 DEMAND_NOT_FOUND` 统一显示“需求不存在或不属于当前业主”；其他失败仍为错误。501、网络故障和非法响应均不算读取成功。
- 显式查询返回跨需求或 draft/rejected 报价时，整次读取失败，不静默过滤成空列表。合法空数组正常显示暂无可对比报价。未知金额仍保留 null，已知小计从明细汇总。
- 每份报价独立显示 `Quote.source`：mock 为模拟报价，live 为非模拟报价数据，缺省为来源未知。整批 `meta.source` 另行展示，不推断每份报价来源；服务方资料来源也独立展示。资料读取失败仍保留报价、以服务方编号和名称待确认提示展示。
- 登录后需点击“重新加载”；已加载页面用“刷新报价”重新查询。刷新或更换需求沿用原有状态保护，立即隐藏旧数据，迟到响应不覆盖新需求。本次未增加自动轮询或登录事件联动。
