# B → D/C：报价 POST 处理器接入与剩余会话阻塞

日期：2026-11-14。基于 main `cb216b0`，PR #58 原子幂等内核及 PR #62 导入边界/重放决策均已合入。

## 已完成的 B 部分

公开 `POST /api/quote` 调用的 `handleQuoteSubmission` 已连接 `createQuoteAtomically`，移除预检通过后的固定 501。处理顺序为：服务端身份预检 → 幂等键 → JSON/输入与整数计价校验 → 事务内重新认证、账户绑定、回执摘要及需求授权 → 原子提交或重放。需求不再在事务外预查，避免已签约需求遮蔽同键不同摘要的 `IDEMPOTENCY_CONFLICT`。

- 事务提交完成才返回 `201 envelope(Quote)`；同键同摘要且当前授权通过返回原报价 `200 envelope(Quote)`，来源均为持久化数据 `live`。
- 缺失/非法键、非法输入、计价溢出、数据库范围超限为 400；身份及业务拒绝继续使用 D 冻结的 401/403/404/409 代码。
- 明确的 P2034/P2002 冲突耗尽内核的三次重试后为 `503 DATABASE_UNAVAILABLE`，提示保留原键与原输入，不宣称此前未保存。
- 其他无法可靠分类的异常，包括连接丢失、坏数据库输出和响应构造失败，保守返回 `500 INTERNAL_ERROR`，提示提交结果无法确认；不暴露内部错误，不自动重试。这也避免把事务内的输出 ZodError 当成客户端输入 400。已用真实提交后人为丢失确认的夹具验证：首次 500、数据库已有一对记录，同键重试 200，未产生重复报价。
- GET 仍使用既有 mock；本 PR 不新增查询参数、不读取真实报价、不宣称 C→A/B 闭环完成。

## 请求 D 完成的精确接入

`src/lib/server-auth.ts` 的默认 reader 目前仍为 `noVerifiedSession`；没有已验证的登录会话。公开 POST 因而仍先返回 401，不存在可以真实登录后提交的完整用户流程。此次接通的是 HTTP 处理器与事务内核，不是登录系统。

请 D 提供两个服务端适配入口，与 B 的 `QuoteSubmissionAuth` 参数匹配：

1. `readSession(request)`：返回经验证的公共 `VerifiedSession` 或 null，验证签名、过期、撤销；不采信角色导航、请求体或自报服务方请求头。
2. `readTransactionSession(request, tx)`：在当前 Prisma 事务上重新核验会话及账户/服务方关系；不返回预检身份缓存。B 内核仍用当前 User.providerId 与 ServiceProvider 复核绑定。

处理器默认两者都使用 D 的空 reader，测试通过显式参数注入合成会话和隔离 SQLite；生产代码不提供测试登录、认证绕过或临时身份。D 适配器合入后，由 B 在 route 的服务端调用处传入这两个入口，不允许 HTTP 请求决定适配器或数据库。

请 D 同步 `docs/API.md` 和 `D-quote-idempotency.md`：移除“预检通过固定 501”的旧实现说明，保留“默认会话未接入，实际请求 401”；记录以上 201/200、缺失键 400、明确冲突 503、未知结果 500 行为及 `INTERNAL_ERROR` 响应。没有新增 DTO、字段、依赖或 schema。

## C 的接入与限制

现有公共 `apiPost`、`QuoteSubmissionInput`、`IdempotencyKey` 和 `envelope(Quote)` 无字段变化。C 应继续区分结果未知与确定的本次拒绝；失败或权限变化不证明以前的同键提交没保存。尤其 `409 INVALID_STATE` 可能发生在历史记录已经保存、需求随后签约时，须保留原键和原输入，不能自动换键重报。D 的冻结规则也要求如此。

真实会话适配器和报价读取协议仍需 D/B 后续完成；GET 真实查询及浏览器登录提交验收不属于本 PR。不要将临时数据库中合成身份的 201/200 测试描述为真实用户登录或业主可见验收。

## 验收覆盖

- 真实路由默认认证优先，伪造身份不会消费请求体；未登录 401、非服务方 403。
- 合法服务端适配参数下，处理器在隔离 SQLite 实际写入、断开重连重放、保留 null/零元和逐行舍入结果。
- 需求已签约时不同摘要仍优先 409 冲突，同摘要 409 状态错误；已有记录保持不变。
- 事务内身份丢失、换绑、需求不存在、非 published、演示需求、坏输出均无成功回执。
- 故障注入验证输出校验回滚和提交确认丢失后同键恢复；未知错误不重试或泄露异常。
