# B → D：报价幂等协议与事务内认证

状态：D 的 PR #57 已冻结协议，权威决策见 D-quote-idempotency.md。下文保留原提案背景；B 现已接入持久化幂等及授权核心，但公开 POST 未接入写入。新增两模块的导入边界仍待 D 放行，详见 B-quote-idempotency-boundary.md。

## PR #57 之后的接入进展

- 使用公共幂等键/摘要工具及两个授权函数。账户角色、一对一绑定、服务方存在性、需求授权均在事务内复核。
- 报价和回执同事务写入；同键同摘要重放，同键不同摘要冲突，不同键及不同服务方按 D 规则隔离。所有回执读取也受当前授权约束；当前非 published 仍返回 409，历史重放读取规则待 D 澄清。
- 写入前按 DatabaseMoney/DatabaseInt 拒绝超范围金额及工期；只对明确的事务/唯一冲突有限重试整个事务，不自动重试未知连接故障。
- 真实会话适配器和公开 POST 尚未接通，内部返回结果不是 HTTP 成功回执。GET 报价继续为 mock。

以下为 PR #57 之前的原始提案与验收要求，已冻结部分以 D 文档为准。

## 当前缺口

- Quote 只有随机主键，没有幂等键、请求摘要或唯一业务约束；请求体也没有重试标识。仅先查再写或进程内 Map 不能保证多进程、重启、并发时不重报。
- D 的默认会话 reader 返回 null，User 与 ServiceProvider 没有账户绑定关系。仅把旧身份再次传入函数不等于重新认证。
- 当前 GET 报价仍为固定 mock，即使完成写入也不能宣称 C → A/B 的闭环已接通。

## 请 D 冻结的协议提案

1. **请求头**：POST /api/quote 必填 `Idempotency-Key`，建议 16–128 位 ASCII 字母、数字、`-`、`_`；缺失/非法返回 400。公共校验、apiPost 的可选头支持、docs/API.md 由 D 维护，C 在一次提交及不确定重试时保留同一键，修改输入后使用新键。QuoteSubmissionInput 请求体保持不变。
2. **持久化**：新增 QuoteSubmissionReceipt（名称可由 D 调整），包含 providerId、key、requestHash（SHA-256）、quoteId、createdAt，并对 `(providerId, key)` 建唯一约束；quoteId 关联报价。回执与 Quote 在同一事务提交，失败一起回滚。请求摘要使用公共 Schema 规范化后的 demandId/items/estimatedDays，字段顺序固定，保留明细顺序、null 与 0 的区别；不能仅用摘要作幂等键，否则无法区分用户新的相同报价意图。
3. **重放和冲突**：同一服务方、同键同摘要返回原报价，不新增；同键不同摘要返回 409/IDEMPOTENCY_CONFLICT，不覆盖旧报价。建议首次 201、重放 200，均为 envelope(Quote)。不同服务方同键互不影响。不同键是否允许同一需求的新报价、是否取代旧版本，仍请 D 明确，B 不自行决定。
4. **认证和授权**：提供事务可用的已验证会话适配器，重新验证签名/过期/撤销、当前账户角色、账户与服务方绑定，并使用传入的 Prisma 事务客户端读取相关记录，不能复用预检快照或绕开事务查询。请明确服务方对具体需求的可见/可报价权限；数据库当前没有这些关系，不能仅凭 provider 角色宣布完成授权。
5. **处理顺序**：事务内重新认证及授权后查询幂等回执。存在同摘要回执时，作为读取已完成结果处理（仍需当前读取权限），不新建；首次写入时必须重新查询同一需求并确认 published、非演示，再写报价及回执。请 D 确认已成交/已撤销需求重放时的读取规则。并发唯一冲突或事务冲突应有限重试整个事务，每次重新认证和读状态，不能只重试 insert。
6. **金额与失败语义**：公共 Money/estimatedDays 接受安全整数，当前 Prisma 使用 Int。请 D 核实数据库/驱动可持久化范围，并冻结超出存储范围时的校验；B 不暗改公共上限。C 当前将 503 视为失败，写入开启前还需 D/C 明确“事务确定回滚”与“提交结果未知”的区别，不得把连接中断一概描述为未保存。

## 本次 B 的独立实现

- `createQuoteAtomically` 使用现有 Prisma Serializable 事务：重新调用 D 的身份验证入口、核对原身份、读取当前账户/服务方，再通过 `findDemand(id, tx)` 读取需求，最后写入服务端计价的 Quote。
- 它只返回已提交事务的 QuoteDTO，错误向外抛出；输出校验也在事务内，失败回滚。身份适配器是必填服务端参数，未提供演示登录默认值。
- 测试仅使用临时 SQLite 和合成会话/数据，不连接用户开发数据库。事务内回查、失败无写入和插入后回滚均由测试验证。
- **该内核没有幂等，也未完成细粒度授权；公开 POST 不调用它。** 当前 HTTP 无真实会话仍为 401，认证及预检通过仍为 501。合入本 PR 不表示报价提交已开放或可以绕开以上阻塞。

## 接通前验收

- 同键并发、超时重放、多进程和重启后只产生一份报价；不同内容冲突不覆盖。
- 事务内身份过期/撤销/换绑、需求变更或删除拒绝首次写入；事务失败没有报价或回执残留。
- 非授权用户不能通过重放读取报价；演示需求不能接收真实写入。
- C 获得成功回执后，A/B 通过冻结的真实查询协议读取同一 demandId 的报价；各失败路径及来源如实显示。
