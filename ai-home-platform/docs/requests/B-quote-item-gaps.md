# B：报价列项差异（缺项核对）提醒

基线：origin/main `917b960`，分支 `feature/B-quote-item-gaps`。对应 B P1 的缺项提醒。单位提醒在独立 PR #109 中，本分支从 main 开始，不包含该 PR 的提交。

## 行为与边界

`/owner/quotes/<id>` 在报价明细前新增“报价列项差异”区。例如两份报价提及垃圾清运，第三份的明细和待确认列表均未提及，页面列出前两份报价及明细行号，再标出第三份待核对。这里的“缺项”是报价之间的名称差异，不是对施工责任或需求完整性的判断。

- 使用公共 DemandDTO、QuoteDTO。只分析同一需求已提交/已接受的至少两份报价；草稿、已拒绝和其他需求报价不参与参照。
- 名称仅去除首尾空白后精确匹配，不把 `line-1` 等局部编号当统一项目，不猜同义词、套餐包含范围或必做项目。
- 明细中的未知费用与零元均算已提及；仅在 `pendingItems` 出现也算已提及，并显示“仅列于待确认项目，尚无同名明细”。不能把待确认误报为完全未提及。
- 同名重复行保留所有原始行号，但差异数量按名称计；空明细可以提示待核对，空列表/单份报价/全空白名称不制造跨报价差异。
- 不补零、不修改合计或来源、不按差异数排名。页面明确未提及不代表漏报或免费，未出现提醒也不代表覆盖完整需求；同名仍需核对施工范围。
