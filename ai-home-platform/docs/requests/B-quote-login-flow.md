# B：密码登录与报价写读串联验收

基线为 origin/main `6b0561b`。#92 页面 PR 尚未合入，本 PR 从 main 独立建立，只增加 B 的集成测试和交接记录，不改业务实现、公共契约、依赖或配置。

## 本次解决的验收缺口

此前 B 的写入测试使用演示登录 cookie，读取测试则直接通过内部函数签发业主会话；未在同一场景串联密码登录、公开报价提交和业主读取。

`tests/B-quote-login-flow.test.ts` 创建临时 SQLite，在加载默认 Prisma 单例前设置独立 DATABASE_URL，使用 D 的账号开通函数准备两个合成业主，并预置归属明确的 published 需求。会话只通过公开 `/api/auth/owner`、`/api/auth/demo-provider` 路由取得；报价直接调用公开 `/api/quote` 路由导出的 GET/POST，使用默认数据库和鉴权逻辑，不注入 reader、不直接签发凭证、不 mock fetch。临时目录清理前校验路径；测试恢复环境变量，不修改开发库或 .env。

已覆盖：

1. 密码登录后读取空列表，服务方首次提交 201，断开数据库重连后业主读回同一报价；0.145 × 100 分舍入为 15 分，null 与零元分别保留，提交和读取均标 mock。
2. 同键重放 200，ID/内容/来源一致，报价及幂等回执仅一条；需求完成后重放 409，但业主仍可读取已提交报价。
3. 匿名 401、仅服务方 403、跨业主与未知需求统一 404；拒绝不会修改已保存报价。另一业主可读取自己的空需求。
4. 同一浏览器携带业主和演示服务方 cookie 时，提交和读取使用各自身份；重新登录另一业主后不能读取原需求，旧业主 cookie 被撤销，不回退服务方身份。
5. 退出业主登录后原 cookie 读取被拒绝；再次通过密码登录可读取原报价，无需重复提交。
