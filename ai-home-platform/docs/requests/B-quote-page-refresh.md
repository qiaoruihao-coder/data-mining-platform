# B：返回报价页自动重新读取

基线：origin/main `b7b08e4`，已包含 #92 报价页接线和 #96 登录写读集成测试。此次只修改 B 页面和私有事件辅助模块，增加回归测试，不改公共契约、依赖、配置或共享登录组件。

## 行为与验收

业主在另一个标签页操作、或离开浏览器窗口后回到 `/owner/quotes/<id>`，页面自动重新调用已有带 demandId 的读取流程，核验当前权限并读取最新列表，无需额外点击刷新。页面保留“刷新报价”按钮，并说明返回会重新读取。

- 初次挂载沿用原来的读取 effect，不额外发请求。
- 监听窗口 blur/focus、文档 visibilitychange；同一次返回相邻的 focus/visible 事件只触发一次刷新。隐藏状态不会因恢复事件发出额外查询；没有定时轮询。
- 监听 pagehide/pageshow，在浏览器缓存恢复时重新读取；首次非缓存 pageshow 不额外读取。
- 刷新复用 attempt 标识和旧请求清理逻辑：立即切到加载状态并隐藏旧报价，迟到结果不能覆盖新的请求。401/403、404、501 等仍走现有失败界面，不降级为演示列表或空成功。
- 卸载清理所有事件监听，React effect 重挂载不残留旧回调。

## 实际验证

- 定向 21/21 通过：新增 5 项事件/读取器测试，以及原有需求报价和读取反馈回归。覆盖事件两种顺序、后台挂载、缓存恢复、清理重挂载、返回后读到新增报价及会话失效不回退。
- `npm.cmd run check` 通过：544/544，lint、类型、模块边界通过。`npm.cmd run build` 通过；`npm.cmd run scope -- --role B --base origin/main` 通过（4 个 B 文件）。已审阅全部差异，`git diff --cached --check` 通过。

## 限制与来源

没有新增 mock 或改变数据来源规则。事件测试使用 EventTarget 模拟浏览器事件；读取器接线用合成 fetch 响应。未做真实浏览器焦点、前进后退缓存或 C 表单提交验收，不将 Node 测试当作浏览器验收。

当前页直接操作共享登录面板不会产生页面离开/返回事件，仍需点击“重新加载”或“刷新报价”。自动订阅共享登录事件需 D 提供统一通知，本次不通过 DOM 监听按钮、读取 cookie 或轮询猜测登录状态。服务方资料及演示身份报价仍标 mock；完整创建需求到报价的浏览器链路仍待 D 的 #95 合入后联合验收。
