# B：服务方资料故障不隐藏已读取报价

基线：main `05da047`。本次独立于尚未合入的演示报价提交 PR #74。

## 行为与验收

报价页此前将需求、报价和服务方资料的任何读取失败都作为整页失败。现在只有需求和报价必须成功；服务方资料仅补充名称，读取失败时保留已经校验的报价，按服务方编号显示“名称待确认”，同时披露资料读取失败、来源未知和刷新入口。HTTP 501 单独显示“资料接口尚未开放”，不采用失败响应携带的名称或来源。

来源继续分别展示：需求来源、报价来源不因资料故障改变；未取得的资料没有 mock/live 标签，不回退固定服务方资料。整体信封来源汇总已取得的数据，服务方未取得的状态通过独立警告展示，不声称资料加载成功。刷新重新读取所有数据，成功后恢复名称并清除警告，再次失败则不沿用旧名称。空报价不请求服务方；成功返回空资料列表与接口失败区分处理。

验收页面：`/owner/quotes/demo-demand`。模拟 `/api/provider` 故障时仍看到报价明细、金额和待确认费用，服务方名称变为编号加待确认；恢复接口后点击“刷新报价”恢复名称。模拟 `/api/quote` 或需求接口故障时仍应显示整页错误，不返回空成功。自动测试覆盖这些分支以及 501 伪成功、损坏数据、累计金额溢出；未进行浏览器故障注入验收。

## 范围与未完成项

仅修改 B 的客户端加载器、展示组件、反馈及测试，不修改公共契约、依赖、配置或其他角色模块。新增字段是 B 页面内部状态，不是公共 API DTO。测试使用合成 fetch 响应，当前公开报价及服务方 GET 仍为 mock，不代表数据库报价查询已接通。

`GET /api/quote?demandId=` 的公共查询契约、事务业主授权器和真实业主会话仍待 D 交付；来源持久化问题与 PR #74 的旧测试更新请求保持待处理，本 PR 不绕过这些依赖。生产读取接通后，服务端权限失败仍应让报价读取失败，不受本次可选资料容错影响。

实际验证：定向测试 18/18 通过；`npm run check` 通过（416/416 测试、lint 无警告、类型与导入边界通过）；`npm run build` 通过；`npm run scope -- --role B --base origin/main` 通过（6 个 B 文件）；`git diff --check` 通过。
