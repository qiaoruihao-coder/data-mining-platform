# B → D：真实报价读取的参数与授权协议请求

日期：2026-11-14。基线 main `cb216b0`；报价写入内核已合入，POST 处理器接入见 PR #67（本分支不包含该 PR）。

## 本次 B 独立完成的部分

`src/lib/quote-engine/read.ts` 提供未接公开 GET 的读取内核。它必须显式接收服务端 `authorizeRead(request, demandId, tx)`，只接受明确的 true；返回 false、无返回值或抛错都不能继续读取需求及报价。授权、D 的 findDemand 和报价读取使用同一 Serializable 事务，不使用预检身份或需求缓存。该函数没有默认允许的授权器，也没有生产环境的测试身份。

授权通过后，需求不存在返回内部 null；存在但无可对比报价时返回公共 envelope(Quote[]) 的空数组。数据库过滤 demandId 及 submitted/accepted，按 ID 升序稳定展示，不按 ID 推断提交时间或最新版本。结果再次检查范围，经公共 Quote 校验并逐行重算小计；null 和额外待确认费用保留。JSON、契约、溢出或查询错误均抛出，不返回部分成功、空成功或固定演示数据。来源沿用 D 的需求来源规则，演示需求的数据库记录仍为 mock，真实需求为 live。

授权适配器由 D 提供；测试中的合成会话/所有者判断仅为隔离夹具，不是冻结的公共权限政策。公开 GET 和页面仍沿用已开放的无参数 mock 协议。本 PR 不新增公共参数、不改变调用方或开放真实数据访问。

## 请 D 冻结并合入的公共协议

1. 参数建议：`GET /api/quote?demandId=<id>`。新增公共 `QuoteQuery`/DTO，字段 demandId 复用 DemandIdParams 的 ID 规则；显式查询不允许空、纯空白、重复参数。非空 ID 原样精确查找，不修剪或回退默认需求。请明确未知参数是否拒绝；建议拒绝。无参数入口建议继续固定 demo/mock，保留兼容。
2. 读取授权建议：已验证的业主只能读取数据库 DemandOrder.ownerId 等于当前 userId 的需求；事务中重新核验账户角色和会话撤销状态。不信任请求头/查询参数中的 ownerId/providerId，也不能复用“服务方可报价”的 authorizeProviderQuote 作为业主读取权限。请明确服务方和管理员的读取范围；在政策确定前建议拒绝这些角色通过业主比较接口查看其他服务方报价。
3. 请 D 提供事务读取授权函数及真实会话适配器，明确 401（无会话）、403（无权）与 404（不存在）的判定顺序及是否隐藏资源存在性。B 内核当前只提供内部 QuoteReadDenied/null/异常，不提前固定这些公共错误映射。授权函数可抛 D 定义的拒绝错误；必须在报价查询前完成验证，不仅检查角色字符串。
4. 成功仍为 `200 envelope(Quote[])`，不新增金额或报价 DTO。业主对比仅 submitted/accepted；空列表与需求不存在分别处理。请求 D 确认签约/施工中/完成需求是否允许业主读取已提交和已接受报价，勿照搬写入的 published 限制。历史幂等回执重放仍遵守 PR #62，与业主读列表是两个权限场景。
5. 失败建议：非法参数 400/VALIDATION_ERROR，无会话 401、无权限 403，合法且可暴露的不存在需求 404/DEMAND_NOT_FOUND；读取或损坏数据 503/DATABASE_UNAVAILABLE，不回退 mock。鉴权查询响应应禁用缓存，防止跨用户复用；请 D 在 docs/API.md 写明。
6. 真实服务方资料/名称的读取协议也待 D 提供。当前 GET /api/provider 是 mock；即使报价来源将来为 live，页面仍须独立标识服务方来源，不能将整页称为全 live。

涉及 D 的文件：`src/contracts/index.ts`（查询 Schema/DTO）、`src/lib/server-auth.ts` 或 D 新授权模块及测试、`docs/API.md`，必要的服务端导入边界由 D 维护。B 不修改这些文件，不新增依赖或数据库字段。
