# B：同名报价项目的计价单位差异提醒

基线：origin/main `8899005`。分支：`feature/B-quote-unit-differences`。对应 B P1 的“不一致单位提醒”；本次不扩展到缺项识别或匹配排序，不修改公共契约、依赖、配置和其他角色目录。

## 行为及验收

在 `/owner/quotes/<id>` 中，同一需求的至少两份已提交/已接受报价存在同名项目且单位不同时，在逐份报价表之前显示提醒。例如“防滑施工”在报价 A 按 1 项计价，在报价 B 按 45 平方米计价，提醒会列出两份报价的编号、原始明细行号、项目编号、数量和单位。

- 复用 `src/contracts` 的 DemandDTO、QuoteDTO 及明细单位类型；私有分析模块只生成展示用分组，不新增 API DTO。
- 名称只去除首尾空白后精确匹配，不把 `line-1` 等局部编号当作跨报价项目身份，不猜别名、同义词或材料范围。
- 不同需求、草稿和已拒绝报价不参与分析；单份报价、同单位、空白名称和空列表不制造跨报价提醒。重复编号或同名多行保留原始行位置。
- 待确认费用和零元项目都参与单位核对；不换算单位、不修改金额、来源或排序，不据此给出最低价结论。
- 页面明确同名不代表施工范围相同，未出现提醒也不代表可直接比较；提醒引用的来源继续由下方逐份报价标识说明。
