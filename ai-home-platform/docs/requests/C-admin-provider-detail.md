# C：售后工单追溯责任服务方资料

基于 main `413fbd6`，本次只完成任务书“工单能追溯到原项目和服务方”中的服务方资料查看。

## 问题与交付

此前管理端工单仅显示责任服务方编号，无法查看关联资料。现在责任方非空时可从 `/admin/tickets` 打开 `/admin/provider/[id]`，查看名称、城市、服务类型和标签，并刷新或返回工单；责任方为空时保留未指定提示，不补默认编号。

- 复用公共 `GET /api/provider`、`Provider` / `ProviderDTO` 及 API 客户端，按完整编号精确匹配。链接编码编号，页面针对当前 Next 14 的路由参数只解码一次，保留中文、空格、斜杠、百分号及字面 `%2F`。不裁剪编号、不忽略大小写、不回退到第一条或演示服务方。
- 资料来源与工单来源分别显示。mock 明确为模拟演示，live 也不代表身份、资质、责任或能力认证；不展示缺乏统计依据的评分或绩效。
- 成功列表没有匹配项时保留请求编号和查询来源，说明“本次列表未找到”，不据此认定服务方不存在或责任解除。空名称、城市和标签有占位。
- 加载、错误、空结果与成功状态分开；刷新时清除旧资料，卸载后忽略迟到结果。重复编号、坏响应、网络及 401/403/404/501/503 返回失败；列表请求的 404 不算资料不存在，501 即使带成功信封也不算成功。
