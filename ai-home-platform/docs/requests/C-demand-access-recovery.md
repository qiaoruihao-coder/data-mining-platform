# C：服务方需求读取的业主会话恢复

- 基线：2026-11-14，main `0f1f0ea`（包含 #101、#106）。
- 场景：`GET /api/demand` 与详情优先验证业主 cookie。过期凭证会导致 401，即使服务方已经登录；顶部业主状态刷新成 signed_out 后没有退出按钮，原有笼统加载错误不能帮助用户恢复公开浏览。
- 本次仅接入已有 `DELETE /api/auth/owner`、`OwnerSessionState` 和公共 `apiDelete`，没有新增接口、契约、依赖或共享配置。D 已实现同源退出、服务端撤销及清除业主 cookie，C 不自行操作凭证。

## 用户行为

1. `/provider` 和 `/provider/demand/[id]` 将需求读取的 401/403 说明为业主登录失效或权限问题。已知 `401 UNAUTHENTICATED` / `403 FORBIDDEN` 提供“退出业主会话并刷新页面”；未知错误码或坏响应不开放退出入口。登录仍可通过现有顶部组件完成，完成后手动重新加载。
2. 页面进入、报错及角色切换不会自动退出。点击按钮才退出当前浏览器业主会话；页面提前说明会刷新本页且保留独立的演示服务方登录。只在接口成功、公共 Schema 通过、source 为 live 且状态为 signed_out 后整页刷新，让顶部登录状态和需求查询一起更新。
3. 等待中禁用恢复按钮并防止重复发送；离开恢复组件后，迟到的请求结果不触发整页刷新。网络中断、501、503、无效或 mock 回执均不宣称已退出，不自动刷新，可由用户明确重试。
4. 需求读取失败不展示旧需求、来源或报价表单，不回退成功空列表或固定 mock。退出成功也不保证详情可访问：公开详情重新查询，私有或不存在的详情仍按服务端 404 处理。

## 验收与限制

本次不新增运行时 mock，测试响应/账号仅为合成数据。需求和服务方演示来源继续显式展示；退出操作使用实际账号会话接口，拒绝 mock 成功回执。

真实接单、生产服务方认证、管理员专属读取、跨页面身份变化自动刷新未包含在本次。全局业主登录组件与其他角色页面仍由各自负责人维护；本次恢复入口仅出现在服务方大厅及需求详情的已知身份错误中。
