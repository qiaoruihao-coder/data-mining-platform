## C 本次独立完成的部分

- 沿用现有详情页面路径，不新增 API。以公共 `DemandIdParams` 校验 ID、编码单个路径片段，通过 `apiGet` 和 `Demand` 校验单条响应；返回 ID 不一致时按错误处理，不回退到其他记录。
- 展示单条响应的 `meta.source`，不继承混合列表的 mock 来源。撤下“详情取自当前列表”的过渡说明；模拟需求保持明确标识，live 不代表身份鉴权已完成。
- 仅已发布需求展示详情与本地报价表单；其他状态只提示“当前需求暂不可报价”。HTTP 404 且错误码为 `DEMAND_NOT_FOUND` 时提示“需求不存在或不可查看”；坏响应、网络异常、501、503 均为错误，支持重试。
- 详情、加载、错误、刷新及返回大厅已实现；报价仍仅在页面内存中预览，不持久化、不提交、不接单。角色导航和客户端隐藏不是鉴权，报价提交请求另见 `C-quote-submit.md`。

## 需要 D 提供

1. 已提供 `GET /api/demand/[id]`，以公共 `envelope(Demand)` 返回单条需求；C 校验响应的 `data.id` 必须等于请求 ID。
2. 继续复用现有 Demand 字段与 DemandIdParams，不申请新增业务字段或复制 DTO。id 为非空字符串；城市、描述、状态、改造类型、面积、预算上下限和期望天数仍按现有契约，金额单位为人民币分。
3. 服务端确认服务方可查看范围并实施鉴权和数据隔离；未经授权不得返回草稿或其他私有记录。当前 C 页面仅展示已发布需求，后续已接单需求访问范围请单独明确。
4. 非法 ID 返回 400；不存在或不可查看的资源返回 404（不泄露私有资源是否存在）；未实现时为 501。错误均使用公共 `ApiFailure`，不得返回 HTTP 200 的默认演示需求作为成功兜底。
5. 更新 `docs/API.md`，补充单条查询、来源和授权规则；按需要调整 D 所有的 API、数据访问、mock 及测试。与 `docs/requests/B-demand-query.md` 的需求可一起协调。

## 请求与响应示例

`GET /api/demand/demo-demand`（固定演示来源）

```json
{
  "ok": true,
  "data": {
    "id": "demo-demand",
    "description": "演示需求：浴室防滑改造",
    "city": "深圳",
    "areaM2": 60,
    "budgetMinCents": 3000000,
    "budgetMaxCents": 5000000,
    "renovationType": "elderly",
    "desiredDays": 30,
    "status": "published"
  },
  "meta": { "source": "mock" }
}
```

404 示例：

```json
{"ok": false, "error": {"code": "DEMAND_NOT_FOUND", "message": "需求不存在或不可查看"}}
```
