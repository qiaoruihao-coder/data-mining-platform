# C：接单内核对已接受报价

基于 main `9451411`，上一块 #135 已合入。本次仅为 `/provider/orders` 的每条接单增加按需读取关联报价的入口。

## 行为与边界

- 关联报价面板默认收起，不额外预取；下方原有本人报价列表仍独立读取。打开时复用无参数 `GET /api/provider/quotes` 及现有公共 `Quote.array()` 校验；接口按当前服务方会话限定查询范围，C 不传身份、需求或报价查询参数，也不调用业主报价比较接口。
- 全列表通过契约和唯一编号校验后，按 `OrderSummary.acceptedQuoteId` 原样精确查找，核对 demandId、providerId、accepted 状态及已知来源一致。合法空数组或缺少目标显示无法核对，不使用第一条/同需求其他报价兜底；关联不一致、坏记录或重复编号拒绝展示。
- 显示原记录的已知金额小计、预计工期和待确认费用，复用已有报价明细组件。金额不重算，零与 null 分开，空明细不宣称费用为零或全部确认。接单关系和报价均不代表付款、开工或施工验收。
- 查询整体来源与报价逐条来源分别展示；旧 DTO 缺少 source 保留“未知”，不从接单或整体来源补造。来源明确不一致时拒绝核对。
- 支持收起、重新打开及手动刷新报价；重新打开再次读取，加载或失败移除旧价格和明细，401/403/501/503、坏 JSON、网络失败不变为成功。收起/筛掉接单/刷新接单时卸载查询并忽略晚到结果，不持久化缓存；全局身份变化仍按页面说明手动刷新。

## 未实现与交接

仅修改 5 个 C 文件，没有共享契约、接口、依赖、数据库或配置变更。本次只核对现有接单与本人已保存报价，不新增报价编辑、改价、取消/改选、实际排期、付款或施工验收。生产服务方认证、管理权限及服务方履约申请/审批仍待后续交付。
