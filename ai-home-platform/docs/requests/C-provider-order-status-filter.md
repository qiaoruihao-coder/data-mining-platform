# C：本人接单履约状态筛选

基于 main `6cf4438`，前置 #125 与 D 的履约推进 #130 已合入。本次仅完成 `/provider/orders` 的本人接单状态统计与筛选。

## 行为与边界

- 沿用无参数 `GET /api/provider/orders`，先通过公共 `OrderSummary.array()` 和现有唯一关联校验，再统计所有返回接单。状态选项与类型直接来自公共契约，不发身份或状态查询参数。
- 四个按钮显示全部、已建立接单关系、进行中、已完成的数量；计数始终基于本次完整结果，不随筛选改变。筛选只影响接单明细，保留原顺序、来源与需求详情链接。
- 区分合法全空列表与有接单但当前状态无匹配；可清除筛选回到全部。按钮提供选中态、键盘焦点及两列/四列响应式布局。
- 刷新保留筛选条件，重新读取后更新计数及记录。加载和失败不显示旧记录或统计，不把 401/403/501/503、网络错误和坏数据当作零条成功；不可用状态中没有筛选操作。
- 整体及逐条 mock/live 来源保留。统计不代表全平台订单数、实际履约量、收入、专业验收或服务方绩效；不从报价推导接单，不新增运行时 mock。
