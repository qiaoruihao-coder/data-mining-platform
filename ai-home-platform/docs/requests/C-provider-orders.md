## 本轮 C 接入

- `src/features/c/provider-orders.ts` 仅调用无参数 `GET /api/provider/quotes`，通过公共 `apiGet` 和 `Quote.array()` 校验。身份由服务端决定，不传 providerId/userId，不下载全量后按客户端身份过滤，不回退原 `/api/quote` 演示列表。
- `/provider/orders` 标题及内容改为“本人报价”，四种报价状态均显示并统计；顺序沿用服务端的编号顺序，不声称按提交时间或成交时间排序。已知金额小计、预计工期、报价/需求/服务方编号及关联需求链接保留；关联需求不再公开发布或不可读取时，以详情页提示为准。
- 整体来源与逐条 `Quote.source` 分别展示。当前演示身份让整体来源为 mock，即使单条为 live 也不是生产身份；兼容旧 DTO 时逐条缺失来源仍显示未知，非法值拒绝整份列表。null 单价或金额即使没有 `pendingItems` 也提示待确认；空明细不能宣称费用全部已知，0 分仍为零元。
- 首次进入和手动刷新均重新查询；加载中先移除旧列表并禁用刷新。401 引导演示服务方登录，403 说明业主登录不提供此权限，501 说明未实现，503/网络/坏数据说明无法读取，不展示成功空列表。只有授权成功的空数组显示本人尚无已保存报价。
- 当前页面不监听全局登录组件的身份变化，也没有自动轮询；用户登录、退出或身份变化后需手动点击“刷新报价”/“重新加载”，页面已明确说明。本轮浏览器验收包含退出后的手动刷新清除旧数据。

## 真实接单提案的身份、状态与失败规则

- 身份来自服务端认证，角色导航不是身份来源；未认证、过期或撤销会话为 401，无服务方权限或当前绑定无效为 403。同一事务核验会话、当前账号及服务方绑定，并据此过滤数据，不能只在页面隐藏其他服务方记录。演示模式可使用 D 已提供的固定演示身份，但仍需验证服务端会话并标 mock，不能允许客户端任选 providerId 冒充本人。
- 经授权且没有接单时返回成功空数组；网络失败、权限问题、501/503 不得转换为成功空数组或返回默认演示订单。
- 所有失败复用 ApiFailure；接口尚未实现为 501，存储不可用或读取数据校验失败为 503。个性化查询的成功与失败响应均应使用 `Cache-Control: private, no-store`、`Vary: Cookie`，避免跨身份缓存泄露。分页、排序及总数如需要，由 D 先定义，C 不猜测查询参数。
- 请明确接单关系的生成时机、同一需求多个服务方的归属、报价接受与接单创建的一致性，以及取消/拒绝是否需要新增状态。既有未签约需求和旧 mock 不自动变成接单记录。

## 真实接单提案的后续验收

1. 两个服务方分别只能读取自己的接单；伪造参数、请求头或角色导航不能扩大权限。撤销/过期会话、角色或绑定变化均被重新校验，切换账号不能读到前一身份的缓存。
2. submitted 报价、其他服务方报价、未签约需求不会出现在当前服务方列表；每条接单能追溯同一需求及 accepted 报价。
3. 空列表、401/403、501、503 和刷新后的状态变化可区分，错误不会保留旧记录冒充最新结果。
4. 数据来源明确，演示身份和历史 mock 不因落库变为 live；混合、缺失、非法来源与空列表按 D 确认的协议验收。mock 不表示真实履约；状态和金额均按公共契约校验。

## 剩余范围

本轮不新增契约、依赖、前端兜底 mock、浏览器持久化、写入或接受报价动作，不请求尚不存在的 `/api/provider/orders`。真实接单关系、接受报价原子流程、履约查询与生产服务方认证仍待 D/B 交付；平台管理鉴权仍需 D 处理。C 的本人报价页面接通不能作为上述能力已完成的证明。
