# C：售后工单分类与状态概览

基于 main `6e693f2`。本次为 `/admin/tickets` 增加一个只读统计表，不依赖尚未合入的管理端需求访问 PR #110。

## 范围与验收口径

- 复用原有无参数 `GET /api/ticket`，经过公共 `Ticket.array()` 和唯一编号校验后才统计；不新增请求、接口、DTO、依赖或配置。
- 按公共四种问题分类与三种工单状态交叉计数，展示分类小计、状态合计和总数。一张工单计一次，同一需求或同一服务方下的不同工单分别计数；责任服务方是否为空不改变工单状态。
- 概览位于筛选区之前，始终覆盖本次加载的全部工单，页面明确说明不随关键词、分类或状态筛选改变。现有筛选只影响下方明细，保留关联需求和责任服务方编号。
- 概览独立显示响应的 mock/live 来源；当前接口是固定 mock，不能把模拟计数称作真实客诉、客户满意度、责任认定、处理绩效或全平台统计。没有历史时间字段，不生成趋势、处理时长或评分。
- 只有合法成功空数组显示全零与现有空态；加载、接口失败、501、坏数据及重复编号不显示旧概览或伪造零计数。刷新沿用现有查询，统计与来源同时更新。
- 表格提供列头、行头、单位、范围说明和可键盘聚焦的局部横向滚动区域；沿用已有共享 UI 样式。

## 未实现与交接

本次只有 C 的聚合函数、私有展示组件、页面接线、测试及本记录，共 5 个文件。没有修改鉴权或接口行为，沿用 D 的生产冒烟断言。

工单数据库读取、创建/派单/状态修改/跟进记录、管理员专属认证和查询权限仍待 D 交付；真实接单仍按 `C-provider-orders.md` 的既有请求推进。概览是当前工单快照，不是售后处理闭环或真实舆情监控。
