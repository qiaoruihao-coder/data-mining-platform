# D：需求 DELETE 的业主鉴权与原子删除

日期：2026-11-14；起始基于 main `c0ecb02`，开发中同步至 `6b0561b`（含 #90 登录与 #79 报价读取）。本次仅处理 `DELETE /api/demand/[id]`，不修改 A/B/C 业务文件。

## 先行协议与范围

- 继续使用公共 `DemandIdParams`、`DemandDeleteResult` 和统一信封，不新增 DTO、依赖或数据库字段。非空 ID 保持原值精确查询，不能 trim 后删除另一条记录。DELETE 无请求体，客户端身份字段或自报请求头不参与授权。
- 错误顺序：路径 400 → 方法/同源 Origin 403 → 事务内真实业主会话 401/403/503 → 本人需求 404 → 演示/状态/关联约束 409 → 删除。缺失、跨源 Origin 或 cross-site 请求拒绝；沿用已有 Host/loopback 检查，不信任 forwarded 头。所有响应带 `Cache-Control: private, no-store` 和 `Vary: Cookie`。
- 只接受已持久化的业主凭证；缺失、伪造、重复、过期、撤销凭证或仅服务方演示 cookie 为 401。有效凭证对应账户已不是 owner 为 403；认证存储失败为 503。拒绝认证时不读取需求。
- DELETE 无需读取正文或接受预检身份快照。会话、当前账户、归属、状态、所有关联检查及删除全部在同一个 Serializable 事务中完成；生产入口不能注入绕过认证的 reader。按 id + 当前会话 userId 查询，他人和不存在返回相同的 404，不暴露状态或关联信息。
- 本人 `demo-demand` 仍为 409 `DEMO_DEMAND_READ_ONLY`；只允许本人 draft/published。其他状态为 409 `INVALID_STATE`；存在任何报价（包括 draft/rejected）、排期、付款、评价或工单时为 409 `DEMAND_HAS_RELATED_RECORDS`。不得级联删除关联业务记录。
- 最终 DELETE SQL 同时限制 id、ownerId、可编辑状态及五种关联均为空；影响行数必须恰为 1。条件失效后在同一事务重新查询并拒绝，不能仅凭之前的读取按 id 删除。成功返回 `200 envelope(DemandDeleteResult)`、`meta.source: live`；再次删除为 404，不伪装重复成功。
- 成功输出在提交前用公共契约校验。数据库故障、事务冲突或不确定结果统一为中性 503 `DATABASE_UNAVAILABLE`，提示刷新核实，不能声称此前一定未删除；不自动重试，不回退 mock。事务内拒绝/异常必须回滚。
- 移除 `src/lib/demand.ts` 中旧的无鉴权删除函数及私有结果类型，公共 API 改为调用专用删除处理器。

## 验收计划与交接

隔离 SQLite 与真实随机业主凭证验证本人 draft/published 删除、精确 ID、匿名/伪造/重复/失效凭证、账户角色变化、跨业主 404、演示只读、五类关联保护、事务内状态/归属/关联变化、并发修改与重复删除、写后异常回滚、存储失败以及公开路由接线。测试账号和需求仅为合成夹具，不修改开发库业务数据。

A 已使用公共 apiDelete 和错误信封，本 PR 不改 A 页面；登录提示等 UI 调整由 A 维护。#90 已合入，可使用密码登录凭证；本次定向测试使用 D 内部签发函数准备合成账号凭证，不提供按客户端 userId 签发的接口。需求 POST 当前业主归属、列表/详情隔离及业务联调仍是独立待办。本次不宣称整个需求模块权限保护完成。
