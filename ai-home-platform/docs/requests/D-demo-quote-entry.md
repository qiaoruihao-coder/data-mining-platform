# D：固定演示报价入口与真实业主链路

## 决策及范围

PR #92 的业主报价比较先验证归属。demo-demand 属于没有密码凭证的 demo-owner，因此不能作为无需登录的真实报价比较入口。本轮不为 demo-owner 设置默认密码、不转移其历史需求、不绕过真实报价接口的业主授权。

优先通过 #95 完成维护者开通账号 → 业主登录并创建本人需求 → 演示服务方报价 → 原业主查看报价。需求和密码验证是实际数据库行为，演示服务方提交的报价仍为 mock。这条流程不依赖固定 demo-demand 的业主登录。

## 给 B 的可选演示请求（尚未实现）

如需答辩时固定演示页“打开即看”，请 B 在独立 PR 为明确的 demo-demand 提供仅固定数据的演示分支，使用已有无参数 GET /api/quote；只允许固定 demo-demand 的报价，持续显示 mock，不允许任意需求在 401/403/404/503 后回退到模拟结果。需求数据也须为独立、固定的 mock 入口，不应为了演示放宽真实需求查询权限。

此项涉及 B 的 load-quotes 和页面，仅由 B 修改。D 当前不新增 demo-owner 登录接口，不把可选方案描述为已完成。需求读取规则已明确：#101 将保留匿名已发布需求列表及详情（含已发布的 demo-demand），非公开需求仅所属业主可读；这不放宽报价比较接口的业主授权。
