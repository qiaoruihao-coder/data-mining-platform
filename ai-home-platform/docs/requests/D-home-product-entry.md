# D：公共首页产品入口清理

## 请求与范围

对应 `C-home-scaffold-cleanup.md` 和用户截图要求。从 main `b6b0992`（已含 #170）建立 `feature/D-home-product-entry`，开工工作树干净。

首页仍使用“开工骨架”、A/B/C/D 分工卡片及任务书指引，与当前可访问的业务功能不符。将其改为四个现有产品入口，保留模拟来源与认证边界；核对引用后删除未使用的共享 `ModulePage.tsx`。不修改 A/B/C 业务模块或登录、角色导航逻辑。

| 首页入口 | 现有地址 | 说明 |
|---|---|---|
| 我的装修 | `/owner` | 查看本人需求、施工安排与售后记录 |
| 报价对比演示 | `/owner/quotes/demo-demand` | 查看固定模拟报价的明细与待确认费用 |
| 服务方需求大厅 | `/provider` | 查看已发布需求，登录后填写报价 |
| 运营看板 | `/admin` | 查看当前可读需求、模拟工单与公开评价汇总；不代表管理员认证 |

`/api/health` 保留原有实现和 API 文档入口，不再作为首页功能卡片。无新增字段、接口、依赖、配置、数据库或 mock 数据；不改 `.env`。

## 文案与验收边界

- 首页移除开发分工、开工说明、README/任务书/公共契约路径。
- 顶部显示“功能演示 · 含模拟数据”；明确角色切换只用于导航，访问范围由登录会话决定。
- AI 澄清默认 mock，真实 AI 完整业务验证仍待完成；已有本机供应商配置不能当作完整能力验收。照片、付款、服务方/管理员认证等原能力状态不因首页文案而变化。
- 四个入口沿用当前路由；不添加身份参数，不将进入运营看板描述为取得管理员权限。
- 浏览器核对桌面和手机布局及四个入口；运行 check、build、D scope，检查 diff 后提交。
