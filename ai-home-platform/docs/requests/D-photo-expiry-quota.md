# D：过期照片回收与全局配额

## 具体变更请求（2026-11-14）

上传只清理当前业主过期照片，全局配额却统计全部记录，导致其他业主的过期照片长期占用额度并阻止新上传。本次修复照片存储生命周期；不改公共 DTO、HTTP 协议、配额数值、依赖或 schema（已有 expiresAt 索引）。与业主接单读取 PR 分开验收。

## 行为与边界

- 仍先同源、会话、需求归属/状态与实际图片校验；最后 Serializable 写事务再次确认同一业主及本人需求后，以服务端本次 now 清理所有 `expiresAt <= now` 的 InspectionImage（包括其他业主），再检查业主及全局配额、原子保存整批。
- 有效照片 `expiresAt > now` 保留，不按客户端传入时间/ownerId 删除。客户端仍只能上传到本人需求、使用本人未过期引用；清理不提供跨业主读写入口、不返回其他业主的引用或清理计数。
- 全局统计继续包含清理后所有实际存储记录，而非只给 aggregate 增加过期过滤；整库仍受 5000 张/500 MiB 上限，单业主有效照片仍 50 张/50 MiB。清理、额度检查与新上传同一事务，并发不会各自取得相同额度；任何失败（含配额不足、保存/输出校验失败）都回滚过期清理和新增记录。
- 过期引用到期即不可使用。回收由后续成功上传触发，没有定时任务；删除行/二进制会释放供 SQLite 复用的页，不承诺数据库文件立即缩小或物理安全擦除，不自动执行 VACUUM。
- 上传仍为 201/live（真实保存），照片检查有效引用仍明确 501；本次不提供 mock AI 分析、真实模型、后台清理、预览/删除管理或 A 页面接线。
