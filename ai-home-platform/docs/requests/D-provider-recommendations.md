# 服务方历史订单推荐（2026-11-18）

用户已确认先生成 10 份成交历史，再实现此前讨论的需求聚类与历史推荐。D 集成公共契约、服务端推荐与 C 需求大厅；不修改数据库结构或依赖。

- 单独创建 10 个演示需求及模拟报价，通过接受报价、开工、完成接口生成可追溯历史。日期为实际演示录入时间，不伪造过去施工或真实付款；原 20 条需求保留。
- 按已登录服务方读取已完成且报价/需求关系一致的订单。真实历史默认独立使用；用户需明确选择演示历史才能使用 mock，不混合训练。
- 按当前公开需求和本人所选来源的历史，使用标准化数值（对数面积、预算、工期）与类型特征进行确定性 K-means。每次刷新重新拟合当前小规模样本，新增需求立即参与；群号仅在当前快照有效。
- 只推荐 published、未成交且与服务方城市匹配的需求；排序融合历史相似度、历史群体占比、专长匹配。无历史冷启动使用专长与群体，不伪造历史理由。返回特征说明和聚类概况。
- UI 在服务方需求大厅增加独立推荐区，保留原全部需求列表。提供来源切换、群体筛选、刷新、空状态和错误状态。登录后才可查询私人历史统计。
- 测试覆盖城市/状态过滤、本人历史隔离、mock/live 隔离、确定性与聚类分离、偏好变化与冷启动。构建、全量检查及本机验收。

局限：小规模合成数据验证业务联动，不证明真实推荐效果；服务城市暂以现有单城市资料为准，工期相似度不等于可预约档期。
