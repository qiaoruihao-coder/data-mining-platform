# 艾可思黑客松总方案（完整版）

> **AI 家装履约撮合平台** —— 借 Boss 直聘的撮合逻辑做壳，把公司已有能力（自动报价、施工排期、舆情管控、数据报表）串成一条 AI 驱动的"公平履约"闭环。
> 团队 4 人 / 28 小时 / Web 应用。

---

## 第一部分 · 命题解读与定位

### 1.1 背景矛盾

- 存量房时代：毛坯整装 → 局部改造 / 适老化 / 维修，需求碎片化、个性化（电竞房、书房、老人房）。
- 服务方从"一家独大"变成设计师工作室、施工工作室、材料商、监理多方协作。
- 协作链条越长，质量越难保证 —— 这是平台的核心机会。

### 1.2 公司基因决定切入点（关键判断）

公司明确"**不提供设计，主要做公平体系**"，且已有：自动报价（5min）、数据报表、施工管控/自动排期（ing）、舆情管控。

**因此不选"AI 出设计图"赛道（不是公司基因、28h 也做不出可信效果），而选"协作类·多服务方协同 + AI 履约管理"。**

### 1.3 与 Boss 直聘的类比

| Boss 直聘      | 本平台                  |
| ------------ | -------------------- |
| 求职者发简历       | 业主发需求（AI 帮写需求单）      |
| HR 搜人 / 双向沟通 | 服务方接单 / AI 辅助谈判      |
| 简历真实性认证      | 报价透明化 + 施工履约评分       |
| 沟通后线下流程      | 沟通后进入平台托管履约（**差异化**） |

**差异化：Boss 直聘止步于"匹配"，我们把成交后的履约（报价、排期、资金、售后）也搬进平台 —— 这正是题干"保证整个服务质量"的答案。**

### 1.4 平台闭环总览

```
业主口语描述 → AI需求澄清(结构化需求单) → 智能匹配(找施工队/材料商)
→ AI报价(5分钟预算+多份对比标红异常) → 施工管控(AI排期+照片监工)
→ 资金分阶段托管+售后舆情 → 评价沉淀 → 回流匹配引擎（公平体系）
```

平台不提供设计，只提供撮合与履约标准 —— 与公司定位一致。

## 第二部分 · 创新点（按优先级）

### P0 · AI 需求澄清官（业主侧入口）

业主口语化描述（"我家 60 平老房，想给老人住，浴室要防滑"）→ LLM 多轮追问 → 输出**结构化需求单**（房型/面积/预算区间/改造类型/工期/位置）。

- 创新：把"非标需求"翻译成"可撮合、可报价"的标准件。
- 技术：LLM + JSON Schema 结构化输出，多轮对话。

### P0 · 智能匹配（Boss 直聘式双向撮合）

需求单 → 匹配施工/设计师工作室/材料商；服务方也可"反向看需求"。AI 生成匹配理由。

- 创新：**评分数据回流匹配引擎**，履约好的服务方排名靠前 —— "公平体系"的技术表达。
- 技术：规则过滤（地域/预算/类型）+ Embedding 相似度 + LLM 匹配理由。

### P0 · AI 报价与预算对比

需求单 → 5 分钟自动报价（demo 模拟调用公司报价引擎）→ 业主端可视化预算表；多份报价 AI 自动**逐项对比、标红异常项**（防低价钓鱼、防恶意增项）。

- 创新："报价透明"是家装最大痛点，完美复用公司已有资产。

### P1 · AI 施工管家

自动生成排期甘特图 + 节点验收提醒；业主上传工地照片 → **多模态 LLM 判断进度与质量**。
技术：LLM 生成排期 JSON → 纯 CSS 甘特图；视觉模型识别照片。

### P1 · 资金分阶段托管

按节点付款（签约30% → 中期40% → 验收30%），超预算 AI 风控预警。Demo 用状态机+可视化模拟，不接真实支付。

### P2 · 售后与舆情

AI 客服处理业主抱怨、分类工单（质量/工期/资金/态度）、舆情看板进管理端。

## 第三部分 · 技术栈与环境准备

### 3.1 技术栈

| 层    | 选型                                                                                  | 理由                   |
| ---- | ----------------------------------------------------------------------------------- | -------------------- |
| 框架   | **Next.js 14（前后端一体）** + TypeScript                                                  | 单仓库搞定前后端，API 路由内置    |
| 样式   | Tailwind CSS + 少量手写组件                                                               | 快，图表纯 CSS 手写不引库      |
| 数据库  | Prisma ORM + SQLite                                                                 | 零配置本地开发，10 分钟出底座     |
| AI   | LLM API（Chat + JSON模式 + 多模态）                                                        | 需求澄清/匹配理由/报价解读/排期/监工 |
| 匹配   | 规则过滤 + 评分加权                                                                         | 比纯向量检索可控、可解释         |
| 数据模型 | User / DemandOrder / ServiceProvider / Quote / Schedule / Payment / Review / Ticket | 8 张表                 |

> 工具选型结论：**VSCode**（不是 PyCharm、不是 Qt）。Qt 是桌面 GUI 框架与 Web 应用无关；PyCharm 是 Python 专用 IDE，与 TS 技术栈不符。

### 3.2 每人环境安装清单（约 30 分钟）

| 工具                     | 用途              | 获取方式                                    |
| ---------------------- | --------------- | --------------------------------------- |
| **Node.js 20+（LTS）**   | 运行时             | nodejs.org                              |
| **VSCode**             | 主编辑器            | code.visualstudio.com                   |
| **Git**                | 版本管理            | git-scm.com（装完配 user.name / user.email） |
| **GitHub Desktop**（可选） | 不熟命令行者用图形界面 git | desktop.github.com                      |
| **Chrome/Edge**        | 预览 + F12 调试     | 已有                                      |

VSCode 插件只装两个：**ESLint** + **Tailwind CSS IntelliSense**。

日常开发两条命令：

```bash
npm install      # 拉完代码首次装依赖
npm run dev      # 启动 localhost:3000，热更新，浏览器所见即所得
```

### 省时技巧

1. **先通链路再打磨**：所有页面先用假数据渲染，再逐个接真接口——任何时候 demo 都"能看"
2. `lib/mock-data.ts` 是保命文件：LLM 超时/额度用完时 API 直接返回 mock
3. 甘特图、对比表纯 CSS 手写，不引第三方图表库
4. 三端共用一套组件
5. 初始化：`npx create-next-app@latest` + `npx prisma init --datasource-provider sqlite`

## 第五部分 · 团队协作规范（Git）

### 5.1 开工 30 分钟准备

1. **管理员**：GitHub/Gitee 建 1 个 monorepo（frontend/backend 就在同一个仓库里，按上面的目录结构），写好 `.gitignore`，首次提交推送 main
2. **每个成员**：clone 仓库 + `git config user.name/user.email`；不熟命令行的装 GitHub Desktop
3. **全员演练（15 分钟）**：每人建 `feature/test-名字` 分支 → 提交 → PR → 合并，打通管线再写正式代码

### 5.2 开发日常（4 条命令）

```bash
git pull origin main                          # 开工/提交前先拉
git add . && git commit -m "模块: 做了什么"    # 半小时一提交
git push origin feature/xxx                   # 推送
# 做完发 Pull Request，管理员合并到 main
```

### 5.3 铁律

- **两条分支就够**：main（只放能跑的版本）+ 每人一个 feature 分支；每完成一个 P0 功能合并一次
- **按模块分工不按文件分工**：A 业主端+需求澄清 / B 匹配+报价 / C 服务方端+管理端 / D 后端+数据层；共享文件改前先 pull、改完立刻推
- **密钥不进仓库**：API key 走本地 `.env` + 管理员私聊分发；评委看仓库是加分项
- **24h 节点打 tag**：`git tag demo-v1 && git push origin demo-v1`；现场改崩 `git checkout demo-v1` 一键回退，与录屏双保险

**"王阿姨家 1998 年的老房子，想改成适老化住家"** → 口语描述 → AI 需求单 → 匹配到做过适老化的施工队 → 5 分钟报价对比 → 分阶段付款 → 施工中 AI 监工发现墙面问题 → 验收 → 好评沉淀，下次匹配排名上升。**评委看到的是闭环，不是五个功能点。**

## 第七部分 · 答辩要点（评委追问预演）

- **Q: 和 Boss 直聘区别？** A: 止步匹配 vs 管到履约；家装是重履约场景，钱和质量都在履约段。
- **Q: 多方协作怎么保证质量？** A: 评价回流匹配 + 分阶段资金托管 + AI 监工三重约束。
- **Q: 和公司现有系统什么关系？** A: 不是替代，是把智装天下的报价/排期/舆情能力以 API 形式开放给生态内的小微服务方（设计师工作室、施工工作室正是智装天下现有客户的上下游）。
- **Q: 商业模式？** A: 服务方会员/接单佣金 + 履约托管服务费（类比 Boss 直聘 + 交易担保）。
